# SHRINEVA — website

Marketing and leasing site for **SHRINEVA**, a commercial building (open stilt + three floors) at D-15, Bada Lalpur, Chandmari, Varanasi 221003.

Angular 16 single-page app, pre-rendered per route at build time (static HTML shells with title, description, canonical, Open Graph, `<noscript>` text and JSON-LD), deployed as static files.

## Run and build

```bash
npm install          # Node 18.x
npm start            # dev server
npm run build        # ng build, then scripts/build-seo.js (postbuild)
```

Output: `dist/shrineva/`. `postbuild` writes, from the same route list and domain:

- one `index.html` per route (19 routes: `/property/index.html`, `/spaces/floor-1/index.html`, …)
- `sitemap.xml`, `robots.txt` and `llms.txt` (a plain-text summary for AI assistants, built from the same config)
- `404.html`, which `.htaccess` serves with a real 404 status for unknown URLs
- JSON-LD (Organization, WebSite, Place, WebPage, BreadcrumbList, plus FAQPage on `/` and `/faq`, ImageGallery on `/gallery`) inside each shell; the runtime `SeoService` updates the same element when visitors navigate.

## Where things live

| What | File |
|---|---|
| Property facts (areas, plan figures, contact, address, domain) | `src/app/config/property.config.ts` |
| Nearby projects and the dated footfall evidence | `src/app/config/footfall.config.ts` |
| Page titles, descriptions, routes | `src/app/config/seo.config.ts` |
| FAQ (visible list **and** FAQPage schema) | `src/app/config/faq.config.ts` |
| Marketing copy that is not a measured fact | `src/app/config/content.config.ts` |
| Images, renders, plan sheets | `src/app/config/media.config.ts`, `src/assets/` |
| Structured data | `src/app/core/seo/schema.ts` |
| Lead form delivery | `src/app/core/services/lead.service.ts` |
| Apache rules (HTTPS, www → apex, SPA fallback, caching, headers) | `src/.htaccess` |

**Rule for editing:** change a fact in `property.config.ts` once; pages, FAQ, schema, sitemap text and `<noscript>` all read from it. Do not type areas or distances into templates.

## Add a page

1. Create the page component and add its route in `src/app/app-routing.module.ts`.
2. Add an entry (path, title, description, h1, priority) to `SEO_ROUTES` in `src/app/config/seo.config.ts`.
3. Add the path to the route whitelist line in `src/.htaccess`. `npm run build` fails with the missing path if you forget, because an unlisted path would return 404 on the live host.

## Switch the public domain

The domain in the repo is a placeholder from the original project (`https://srineva.com`) and has **not** been verified or confirmed as the owner's domain. When the domain is decided and registered:

```bash
node scripts/set-domain.js https://shrineva.com     # updates property.config.ts and src/index.html
npm run build                                        # regenerates canonical, OG, JSON-LD, sitemap, robots
```

Nothing in this repository registers, points or verifies a domain.

## Enquiry forms (one owner action required)

Static hosting has no backend, so `LeadService` posts to [FormSubmit](https://formsubmit.co) (recipient: `contact.email` in `property.config.ts`).

1. After the first deployment, submit the contact form once.
2. FormSubmit emails the recipient an activation link. **Click it.** Until then no enquiry is delivered.
3. The site only shows "sent" when FormSubmit confirms delivery. If activation is missing it shows the phone / WhatsApp fallback instead, so nobody is told a lead was received when it was not.
4. The recipient address is visible in the JavaScript bundle (a property of any browser-side form service). To hide it, replace it with FormSubmit's random alias (offered after activation) or use a small PHP handler on Hostinger.

## Analytics

`src/environments/environment*.ts` hold `ga4MeasurementId`, `googleAdsConversionId`, `googleAdsConversionLabel`. They are empty; tracking stays off until the owner supplies them. Events fired include `whatsapp_click`, `phone_click`, `floor_plans_click`, `plan_open`, `plan_pdf_download`, `site_visit_click`, `site_visit_submit`, `leasing_form_submit` and the matching `*_error` events (see `AnalyticsService`).

## Deploy to Hostinger (static upload)

1. `npm run build`.
2. In hPanel → File Manager (or FTP), open `public_html/`, remove the old site files, and upload the **contents** of `dist/shrineva/` (including the hidden `.htaccess`).
3. Confirm SSL is active, then open `/`, `/floor-plans`, `/faq`, `/does-not-exist` (should show the app's page, not a server error).
4. Submit the contact form once and click the FormSubmit activation email.
5. In Google Search Console add the domain, submit `https://<domain>/sitemap.xml`, and inspect `/` and `/growth`.

`.htaccess` behaviours (HTTPS redirect, www → apex, directory index rewrite, cache and security headers) cannot be exercised locally. Check them after upload with `curl -I http://<domain>/` and `curl -I https://www.<domain>/`.

**Rollback:** keep the previous `public_html` contents as a zip before uploading; to roll back, delete the new files and restore the zip. Vercel alternative: `vercel.json` is included (build `npm run build`, output `dist/shrineva`).

## Content rules this project follows

- No approval numbers, floor areas, parking counts, tenants or reviews that the owner has not supplied. Parking capacity is deliberately "to be confirmed".
- Areas are computed from the architect's dimensions (floor area 3,519.75 sq ft, carpet 3,017.25 sq ft per floor) and labelled as such, not certified.
- 3D images are labelled indicative. Nearby projects are described with source and date, and no footfall figure is claimed (`FOOTFALL_NOT_CLAIMED`).
- Setback dimensions and the original architectural drawings are not published on marketing pages.
